# GitHub Actions Release Guide

This project publishes desktop builds through GitHub Releases.

The release workflow is defined in `.github/workflows/tauri-release.yml`. It builds a 4-target matrix (macOS arm64, macOS x64, Windows x64, Linux x64) with `cargo tauri build`, publishes the platform-specific bundles to the GitHub Release, and generates a `latest.json` update manifest for the Tauri updater.

## Why releases use tags

Auto-update must be based on versioned release artifacts, not raw commits.

Each update needs:

- a package version in `src-tauri/tauri.conf.json` (`bundle` / `version`);
- a Git tag that matches that version, such as `v0.3.0-beta.1`;
- a GitHub Release created from that tag;
- packaged artifacts, including the platform bundle used by the updater;
- `latest.json` generated by `scripts/verify/generate-tauri-update-manifest.mjs`.

This keeps unfinished commits from being sent to users.

## One-time repository setup

In GitHub, open:

`Settings` → `Actions` → `General` → `Workflow permissions`

Select:

`Read and write permissions`

Then save.

The workflow also declares:

```yaml
permissions:
  contents: write
```

That is required so the built-in `GITHUB_TOKEN` can create/update releases and upload artifacts.

For update signing, configure the Tauri updater secrets described in [updater-signing.md](updater-signing.md):

- `TAURI_SIGNING_PRIVATE_KEY`
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`

## Publishing a release

1. Make sure the app is ready and committed.

2. Bump the version in `src-tauri/tauri.conf.json`:

```bash
# edit src-tauri/tauri.conf.json -> "version": "0.3.0-beta.2"
```

Keep the `tauri.conf.json` version and the `package.json` version in sync.

3. Verify locally:

```bash
npm run tauri:build
```

4. Commit the version bump:

```bash
git add src-tauri/tauri.conf.json package.json package-lock.json
git commit -m "chore: release v0.3.0-beta.2"
```

5. Create the tag:

```bash
git tag v0.3.0-beta.2
```

The tag must match the `tauri.conf.json` version exactly. `tauri.conf.json` version `0.3.0-beta.2` requires tag `v0.3.0-beta.2`.

6. Push the commit and tag:

```bash
git push origin feat/tauri-migration-v2
git push origin v0.3.0-beta.2
```

GitHub Actions will start automatically.

## Manual workflow run

You can also run the workflow manually:

1. Open the repository on GitHub.
2. Go to `Actions`.
3. Select `Tauri Release`.
4. Click `Run workflow`.
5. Enter a tag such as `v0.3.0-beta.2`.

The tag must already exist in the repository.

## Build matrix

The `build-tauri` job runs a 4-target matrix:

| Label | Runner | Target | Artifacts |
|-------|--------|--------|----------|
| macOS-arm64 | `macos-15` | `aarch64-apple-darwin` | `.app`, `.dmg` |
| macOS-x64 | `macos-15` | `x86_64-apple-darwin` | `.app`, `.dmg` |
| Windows-x64 | `windows-latest` | `x86_64-pc-windows-msvc` | NSIS `.exe`, `.msi` |
| Linux-x64 | `ubuntu-22.04` | `x86_64-unknown-linux-gnu` | `.AppImage`, `.deb` |

Each job:

1. Installs Rust 1.89.0 (pinned — see `RUSTUP_TOOLCHAIN` in the workflow; newer Rust breaks `cargo-tauri` proc-macro linking).
2. Installs Node 20 and runs `npm ci`.
3. Copies the bundled CLI into `src-tauri/resources/cli-package/` via `scripts/verify/copy-cli-resource.mjs`.
4. Installs `tauri-cli` and runs `cargo +1.89.0 tauri build --target <target>`.
5. Uploads the bundle as a workflow artifact.
6. Publishes the bundle to the GitHub Release for the tag.

`RUSTFLAGS=""` is set explicitly because `cargo-tauri` injects LTO flags that break `ctor-proc-macro` linking on Rust 1.89.

## Expected release assets

The GitHub Release should include, per platform:

- macOS arm64: `Verboo Code_<version>_aarch64.app`, `Verboo Code_<version>_aarch64.dmg`
- macOS x64: `Verboo Code_<version>_x64.app`, `Verboo Code_<version>_x64.dmg`
- Windows x64: `Verboo Code_<version>_x64-setup.exe`, `Verboo Code_<version>_x64_en-US.msi`
- Linux x64: `verboo-code_<version>_amd64.AppImage`, `verboo-code_<version>_amd64.deb`

Plus the updater manifest:

- `latest.json` (and per-platform manifests if generated by `generate-tauri-update-manifest.mjs`)

`latest.json` is the important file for updater clients. It references the generated bundle for the client's platform and carries the signature produced by `TAURI_SIGNING_PRIVATE_KEY`.

## Update manifest generation

The `publish-updates-manifest` job runs after all `build-tauri` jobs succeed. It:

1. Downloads all platform bundle artifacts.
2. Runs `node scripts/verify/generate-tauri-update-manifest.mjs --tag <tag> --version <version> --prerelease <bool> --bundles-dir bundles --output update-manifests`.
3. Uploads each generated manifest to the GitHub Release with `gh release upload --clobber`.

## Unsigned macOS limitation

Current internal builds are ad-hoc/unsigned (`CSC_IDENTITY_AUTO_DISCOVERY=false` in the workflow). They are useful for internal testing, but macOS Gatekeeper can still warn or block users on another Mac.

Developer ID signing and notarization should be added before broader public distribution. The GitHub Actions workflow is structured so signing credentials can be added later without changing the release model.

Future secrets likely needed for macOS signing/notarization:

- `APPLE_ID`
- `APPLE_APP_SPECIFIC_PASSWORD`
- `APPLE_TEAM_ID`
- `APPLE_CERTIFICATE` (Developer ID Application `.p12` base64)
- `APPLE_CERTIFICATE_PASSWORD`

When those exist, remove `CSC_IDENTITY_AUTO_DISCOVERY=false` from the build job and configure `tauri.conf.json` macOS signing. This is separate from the Tauri updater signing keys (`TAURI_SIGNING_PRIVATE_KEY`), which sign update bundles for the auto-updater and are already required.
